# ragged-pool 0.2.0

This release packages the current accepted CPU source under a new version. It brings the maintained library and examples into a downloadable snapshot after the initial v0.1.0 release. The earlier tag, wheel, source archive and qualification retain their original identities.

The minor version reflects additive work accumulated since v0.1.0: padded pooling, native second derivatives, selected function transforms, trusted export and training-resume examples, and bounded two-rank Linux CPU demonstrations. Each route keeps its own input and composition limits. The release preparation changes version admission, packaging guidance and publication checks. It adds no numerical algorithm, benchmark result or GPU qualification.

## Download and run

Use the [installed CPU example](https://github.com/T92T1914/ragged-pool/blob/v0.2.0/docs/install.md). The primary release assets are:

| Asset | Contents and scope |
| --- | --- |
| `ragged_pool-0.2.0-cp311-cp311-win_amd64.whl` | Python package and native CPU extension for Windows x64, CPython 3.11.8 and PyTorch 2.9.1+cpu. The build uses MSVC 14.44 and C++17. |
| `ragged_pool-source-<full-release-commit>.zip` | The exact tracked Git source, examples, guides and notices. The actual filename identifies its full commit. It is a source archive, not a Python sdist. |
| `SHA256SUMS.txt` | SHA256 identities for the two primary payloads above. |

Install PyTorch separately from its official CPU wheel index before installing the wheel. The [Linux source-to-wheel route](https://github.com/T92T1914/ragged-pool/blob/v0.2.0/docs/linux-cpu.md) has separate Ubuntu 24.04 x86-64/GCC 13 execution. Neither route establishes cross-version ABI compatibility or support for arbitrary Linux distributions. No manylinux tag is claimed.

## Verification and limits

The [Windows package workflow](https://github.com/T92T1914/ragged-pool/actions/workflows/cpu.yml) builds the versioned wheel and uses a fresh external installation for payload, dependency, license, mathematical, registration and training checks. The [Linux source distribution workflow](https://github.com/T92T1914/ragged-pool/actions/workflows/linux-cpu.yml) builds from a byte-checked proper sdist and accepts its wheel outside the checkout. [CPU AddressSanitizer](https://github.com/T92T1914/ragged-pool/actions/workflows/native-asan.yml) remains a separate instrumented check. Inspect each successful run's actual source revision and logs. A workflow definition alone is not an execution result.

Publication requires the exact project-version/tag pair, matching source revision, reviewed notes and expected payload. It refuses an existing release or draft, compares uploaded asset sizes and server digests, and reads the published identities back. Public downloads should be compared with their recorded hashes before use. Hashes do not authenticate an unknown publisher or establish reproducible builds.

The [tensor contract](https://github.com/T92T1914/ragged-pool/blob/v0.2.0/docs/contract.md) and [examples guide](https://github.com/T92T1914/ragged-pool/blob/v0.2.0/docs/examples.md) retain numerical, transform and artifact-loading limits. `aot_eager` demonstrates graph capture and autograd integration, not optimized code generation. Windows Gloo failure, unfavorable synthetic results and native diagnostic limits remain available in their original records. Responsive Linux ranks do not establish failed-rank recovery.

The default CPU wheel does not contain the separate CUDA extension. The [CUDA companion](https://github.com/T92T1914/ragged-pool/blob/v0.2.0/docs/examples.md#cuda-companion) and [co-installation record](https://github.com/T92T1914/ragged-pool/blob/v0.2.0/docs/coinstallation.md) identify their accepted older packages and their own framework, compiler, hardware and sanitizer scope. The functional mapping bridge is not a fused parallel CUDA kernel. This release does not broaden those claims or qualify a new CPU/CUDA wheel pair.
